# 测试环境运行安全规范

## 1. 目的

本规范用于防止自动化测试、接口调试、浏览器调试、数据脚本和人工验证误访问 Rakumart 正式站。

本项目内的所有调试和测试活动只能在已确认的测试站执行。任何情况下都不得使用本项目对正式站进行登录、查询、造数、支付、退款、问题产品处理或其他业务操作。

## 2. 适用范围

本规范适用于：

- 本地开发和调试；
- 接口自动化、UI 自动化和 Playwright 测试；
- 数据工厂及所有数据脚本；
- 系统回归、Small Suite、单例 UAT 和全量 UAT；
- 登录、购物车、订单、报价、支付、退款、余额和银行流水验证；
- 问题产品、采购、配送、翻译及后台管理操作；
- curl、Postman、Apifox、浏览器开发者工具及临时诊断脚本；
- 人工协助执行的测试步骤。

## 3. 环境域名清单

### 3.1 允许访问的日本测试站

| 用途 | 允许地址 | 规则 |
|---|---|---|
| 测试站后台页面 | `https://jpmanage.rakumart.cn/` | 仅用于日本站测试和验证 |
| 测试站 API | `https://jpapi.rakumart.cn` | 仅用于日本站自动化及接口测试 |

只有上述精确主机名属于当前已批准的日本测试环境。路径、查询参数和 URL 片段不能改变环境归属。

### 3.2 严禁访问的正式站

| 用途 | 正式站地址 | 规则 |
|---|---|---|
| 正式站前台 | `https://www.rakumart.com/` | 绝对禁止用于调试和测试 |
| 正式站后台 | `https://manage.rakumart.com/#/login` | 绝对禁止用于调试和测试 |

所有 `rakumart.com` 主域及其子域默认按正式环境处理。除正常用户在产品中的业务使用外，本项目的自动化程序、测试脚本和调试工具不得向其发送任何请求。

## 4. 强制原则

1. **测试站唯一原则**：所有测试、调试和 UAT 必须在测试站完成。
2. **正式站零接触原则**：不得对正式站执行只读探测、登录验证、健康检查或业务写操作。
3. **默认拒绝原则**：目标域名不在测试站允许清单中，或无法确认其环境归属时，必须停止，不得发送请求。
4. **名称不可作为依据**：项目名、环境名或配置备注中包含“测试”字样，不代表实际域名一定是测试站；必须核对最终解析后的 URL。
5. **最终 URL 原则**：校验对象必须是合并配置、环境变量和参数覆盖之后的最终请求 URL，而不是原始配置或页面显示名称。
6. **重定向同样受限**：测试请求发生重定向时，重定向目标也必须属于允许清单；跳转到其他域名必须立即终止。
7. **禁止绕过门禁**：不得通过代理、hosts、DNS、环境变量、配置覆盖、URL 短链或手工修改请求的方式绕过环境检查。

## 5. 运行前强制门禁

每次运行登录、造单、支付、退款、问题产品或 UAT 前，必须依次确认：

1. 输出并核对项目 ID、环境 ID 和环境名称；
2. 输出最终页面域名和最终 API 域名；
3. 确认页面主机名精确等于 `jpmanage.rakumart.cn`；
4. 确认 API 主机名精确等于 `jpapi.rakumart.cn`；
5. 确认协议为 HTTPS；
6. 确认没有 `rakumart.com` 正式域名；
7. 确认使用授权测试账号和测试客户数据；
8. 确认没有运行中的重复批次或遗留写任务；
9. 记录本次 case ID、batch ID 或 execution ID，保证业务数据可追踪；
10. 完成上述核对后才允许发送第一个请求。

任一检查失败时必须返回环境阻塞结果，不得通过警告后继续执行。建议统一使用：

```text
status = blocked
reason_code = unsafe_environment_target
```

安全证据只能记录脱敏后的环境名称、主机名、端口和检查结果，不得记录密码、Cookie、Token、Session 或密钥。

## 6. 禁止行为

本项目严禁：

- 使用正式站账号验证自动化登录；
- 向正式站发送 GET、POST、PUT、PATCH、DELETE 或其他任何请求；
- 在正式站创建购物车、订单、配送单、采购单或问题产品；
- 在正式站执行报价、支付、退款、补款、余额调整或流水匹配；
- 在正式站运行单元调试、Small Suite、单例 UAT 或全量 UAT；
- 使用正式业务订单或正式客户数据作为自动化测试前置数据；
- 因测试站故障而临时切换到正式站继续验证；
- 将正式站配置复制到测试配置后继续执行；
- 对未知域名进行“试一次看看”的登录或探测；
- 在发现环境错误后自动重试、补单、退款或执行其他补偿写操作。

## 7. 执行过程中的停止条件

出现以下任一情况必须立即停止当前用例和后续批次：

- 最终 URL 包含 `rakumart.com`；
- 页面域名或 API 域名不在允许清单；
- 请求重定向到非测试域名；
- 环境名称与实际域名不一致；
- 无法确认当前连接的是测试站；
- 测试账号被识别为正式账号；
- 返回数据疑似来自正式客户、正式订单或正式资金流水；
- 代理、DNS 或环境变量导致目标地址发生变化；
- 日志中出现正式站域名或正式业务标识；
- 已经发生误请求或疑似误写入。

停止后不得为了确认问题而再次发送请求。

## 8. 误访问正式站的应急处理

如果发现或怀疑测试程序访问了正式站，必须：

1. 立即停止当前脚本、批次和所有自动重试；
2. 不再发送任何登录、查询或补偿请求；
3. 保留脱敏后的时间、目标主机名、case ID、batch ID、execution ID 和业务单号；
4. 检查本地是否仍有运行中的任务，但不得借检查再次访问正式站；
5. 立即通知项目负责人和正式环境运维人员；
6. 由正式环境负责人通过服务端日志确认影响范围；
7. 未获得明确恢复许可前，不得恢复任何真实环境验证；
8. 不得自行删除、退款、撤单或修改正式数据来掩盖影响。

事故证据必须脱敏，严禁在聊天、日志和报告中记录明文密码、Cookie、Token、验证码、Session、Authorization 或私钥。

## 9. 配置和代码要求

- 测试环境配置必须保存明确的测试页面域名和测试 API 域名；
- 不得仅通过“日本站测试”等显示名称判断环境安全；
- 自动化入口应在创建批次和发送登录请求前校验最终主机名；
- 批量执行和单例执行必须使用同一套环境门禁；
- 浏览器自动化、HTTP 客户端和临时诊断脚本都必须执行相同检查；
- 运行记录应保存脱敏后的环境证据，便于追踪实际请求目标；
- 新增站点或域名前，必须先由负责人确认其环境属性并更新本规范；
- 未写入本规范允许清单的域名一律禁止使用。

## 10. 例外规则

本项目的测试和调试流程不设置访问正式站的例外。

如将来确有正式环境运维需求，必须建立独立于本测试平台的正式环境操作流程，使用单独授权、单独账号、单独审计和人工审批；不得通过修改本规范、临时关闭门禁或复用测试脚本来访问正式站。

## 11. 执行确认清单

运行人员在执行任何真实请求前，应确认：

```text
[ ] 页面域名为 jpmanage.rakumart.cn
[ ] API 域名为 jpapi.rakumart.cn
[ ] 未出现 rakumart.com
[ ] 使用测试账号和测试数据
[ ] 最终 URL 已完成校验
[ ] 重定向目标受环境门禁约束
[ ] 没有遗留运行批次
[ ] 本次执行标识可追踪
[ ] 敏感信息不会进入日志或报告
```

任何一项未确认，都不得开始执行。
