# 元数据驱动的数据智能体合同编辑与学习闭环设计

## 背景

当前 DeepSeek 数据智能体已经能够为订单、配送单和问题产品等核心流程生成执行合同，但仍存在三个直接影响使用体验的问题：

1. 脚本能力元数据主要用于筛选和提示模型，没有自动生成通用合同编译逻辑，因此脚本覆盖数量增加后，自然语言首次命中率没有同步提升。
2. 合同编辑由前后端固定白名单控制，仅支持店铺数、每店商品数、购买数量、执行单价和目标状态，客户、支付、问题产品、附加服务等字段无法直接修改。
3. 学习中心只展示规则候选和生效规则，没有样本入口和命中率看板。学习数据只能在任务结束时隐式采集，用户无法判断一条修正是否已经进入学习流程。

本设计以“首次输入生成正确、可确认的执行合同”为首要目标，在保留现有核心流程的前提下，将脚本能力元数据扩展为合同、编辑和学习的统一来源。

## 目标

- 核心订单、配送单、问题产品流程首次合同命中率不低于 95%。
- 其他已接入元数据的脚本首次合同命中率不低于 90%。
- 用户可以通过完整表单或自然语言纠正合同，不再编辑拼接后的展示文字。
- 最终确认合同作为识别标准答案，自动形成可追溯学习样本。
- 学习规则经过样本累计、历史回归和管理员批准后才生效。
- 新增脚本通过元数据即可获得基础自然语言合同、编辑和学习能力。
- 不重写现有核心执行器，不破坏订单、支付、权限切换和问题产品续跑流程。

## 非目标

- 不允许 DeepSeek 自行创造元数据中不存在的脚本参数、执行节点或工具。
- 不将密码、Token、Cookie 等凭据写入学习样本、规则版本或模型提示词。
- 不一次性开放所有高风险脚本执行权限。
- 不在本次范围内重构无关数据脚本或前端主应用。

## 总体架构

每个 `DataScriptCapability` 在现有项目、意图、风险和运行器信息之外，增加三类声明：

### 识别定义

- 支持的自然语言意图和常见表达。
- 单号类型及自然语言别名。
- 适用项目和业务模块。
- 与其他能力冲突时的优先级。

### 合同定义

- 字段名称、标签、类型和默认值。
- 必填条件和值来源优先级。
- 可编辑控件和候选值。
- 字段校验、跨字段校验和结果映射。
- 推断项展示方式。

### 学习定义

- 字段是否允许学习。
- 学习具体值或选择策略。
- 默认项目范围或全局范围。
- 可生成候选规则的规范字段映射。

统一数据流如下：

```text
自然语言
→ 根据项目和模块筛选能力
→ 匹配脚本与意图
→ 合同编译
→ 用户表单编辑或自然语言纠正
→ 最终确认合同
→ 执行与业务校验
→ 保存命中结果和学习样本
→ 累计规则候选
→ 历史回归
→ 管理员批准后生效
```

## 合同编译优先级

合同生成采用三层优先级：

1. 核心专用编译器：订单、配送单和问题产品继续使用现有确定性规则。
2. 元数据合同编译器：根据能力元数据生成其他脚本的结构化合同。
3. DeepSeek 辅助理解：只负责从自然语言中提取候选意图和字段，不负责决定可执行范围。

模型候选必须经过能力范围、字段类型、值来源和跨字段规则校验。任何不属于元数据合同的字段都不得进入执行合同。

## 合同字段定义

每个合同字段统一描述以下属性：

```text
name
label
value_type
required_when
default
sources
aliases
editor
choices
validator
learnable
learning_mode
learning_scope
```

值来源优先级继续遵循已确认业务规则。例如客户 ID 使用“自然语言明确值 → 顶部栏值 → 当前项目环境测试账号”的顺序，并在合同中标注实际来源和推断项。

## 合同编辑器

采用已确认的方案 A：分组展开式编辑器。

### 页面分组

- 任务范围：项目、环境、客户 ID、订单号、配送单号、目标状态。
- 商品与价格：店铺数、商品数、购买数量、关键词、来源、价格口径、总价、单价、运费和其他费用。
- 支付：余额优先、银行支付和余额不足降级策略。
- 问题产品：处理范围、商品序号、退款数量、商品金额、运费和附加服务。
- 执行信息：推断项、操作顺序、合同版本和合同哈希。

字段使用数字框、金额框、下拉框、复选框或单号输入框，不再要求用户修改“1 店 × 每店 2 种”一类拼接文字。合同版本、合同哈希、系统计算合计和已完成步骤保持只读。

### 操作方式

- `重新生成合同`：使用自然语言纠正重新编译，并展示字段差异。
- `合同正确`：将当前合同保存为待验证样本，不执行脚本。
- `保存修改`：校验结构化字段并生成新合同版本。
- `确认并执行`：锁定当前合同后进入现有执行流程。
- `恢复推断值`：单字段恢复本轮最初推断值。

编辑失败时保留用户草稿，在对应字段旁显示错误，不重置整份合同。

## 自然语言纠正

合同确认页保留独立纠正输入框，例如：

```text
客户改成300003，商品改成3种，支付改成银行，第2番全部退款
```

纠正消息以当前合同为基线重新编译，只更新有明确证据的字段。页面必须展示修改前、修改后和证据来源，用户再次确认后才覆盖当前合同。

## 学习样本

最终确认合同是自然语言识别的标准答案。

### 命中判定

- 首次合同与最终确认合同规范化后一致：首次命中。
- 用户修改任一执行字段后才正确：首次未命中，并记录字段修正。
- 只修改显示文字且执行字段不变：不计为识别错误。
- 执行失败不自动判定为识别失败。

### 样本状态

- `pending`：用户点击“合同正确”或确认合同，但尚未获得业务执行校验证据。
- `verified`：合同已确认，任务执行成功且业务目标校验通过。
- `invalid`：用户明确标记识别错误后放弃，或管理员判定样本不可用。

合同修正、澄清消息和结构化编辑均记录初始值、最终值、来源及合同版本。

### 学习范围

- 业务字段、客户 ID、订单号、配送单号和金额规则允许在当前项目范围内形成学习样本。
- 单号类字段可用于学习识别方式和来源优先级；规则不得将某次任务的订单号硬编码到其他任务。
- 账号允许学习项目角色、系统账号选择和权限切换策略。
- 密码、Token、Cookie、授权头和加密凭据永不进入学习数据。

## 规则候选与生效

同一项目、模块、意图、字段和规范化修正值累计 3 个已验证样本后生成规则候选。候选规则必须：

1. 只修改能力元数据声明为可学习的字段。
2. 对来源样本和维护的历史样本运行回归。
3. 不降低已有合同命中率。
4. 由管理员批准后以项目规则生效。

项目规则可以提升为全局规则；规则支持停用、版本回滚和审核记录。未批准规则只能展示，不能注入合同编译。

## 学习中心

学习中心增加四个视图：

- 学习样本：原始输入、初始合同、最终合同、修正字段、验证状态和来源任务。
- 规则候选：出现次数、回归结果、来源样本、批准和拒绝操作。
- 生效规则：范围、版本、状态、停用、提升全局和回滚。
- 命中率：最近 7 天、30 天、按脚本及按字段统计的首次合同命中率。

命中率看板同时展示样本总量和待验证样本量，避免小样本百分比造成误导。

## 错误处理

- 能力无法唯一匹配时只追问区分意图所需的最少信息。
- 字段值不合法时返回字段级错误并保留草稿。
- 自然语言纠正未产生有效变化时明确提示，不生成重复样本。
- 合同版本冲突时要求刷新，不覆盖更新后的合同。
- 学习样本保存失败不得影响业务任务完成状态，但必须记录可定位的错误事件。
- 学习规则回归失败时保持候选状态，不能进入审批或生效阶段。
- 高风险操作继续使用合同哈希和二次确认，不因学习规则绕过确认。

## 分阶段实施

### 第一阶段：核心编辑与样本闭环

- 建立元数据字段定义和合同字段序列化接口。
- 实现方案 A 分组合同编辑器。
- 增加自然语言纠正、合同正确、保存修改和字段差异展示。
- 保存首次合同、最终合同、字段差异、样本状态和命中结果。
- 学习中心增加样本列表和命中率看板。

### 第二阶段：通用元数据合同编译器

- 将能力筛选和字段解析接入通用合同编译器。
- 保留核心专用编译器并优先执行。
- 按脚本补齐别名、默认值、编辑控件和学习配置。
- 低风险脚本通过合同及执行测试后逐个开放。
- 高风险脚本继续保持二次确认和逐项启用策略。

### 第三阶段：学习闭环完善

- 完善待验证、已验证和无效样本管理。
- 自动生成候选规则并运行历史回归。
- 完成批准、拒绝、停用、提升全局和回滚流程。
- 将命中率门禁加入发布验证。

## 测试与发布门禁

- 元数据字段验证及兼容旧注册表测试。
- 核心专用编译器和通用合同编译器优先级测试。
- 表单字段编辑、字段级错误和草稿保留测试。
- 自然语言纠正及合同差异测试。
- 首次合同与最终合同规范化比较测试。
- 学习样本状态转换和去重测试。
- 候选规则阈值、回归、审批、生效、停用及回滚测试。
- 客户 ID 优先级、余额不足银行降级、500 元权限切换和临时凭据脱敏回归。
- 高风险合同哈希和二次确认回归。

发布门禁：

- 核心订单、配送单和问题产品实际样本首次命中率不低于 95%。
- 其他已接入元数据脚本实际样本首次命中率不低于 90%。
- 任一分类命中率不得低于上一发布版本。
- 命中率门禁必须同时报告样本量，不允许仅报告百分比。

## 兼容与修改边界

- 保留现有会话、确认、执行、暂停、权限接管和校验接口语义。
- 新前端逻辑继续放在独立数据智能体模块，不向 `static/app.js` 堆积实现。
- 能力元数据负责描述，不直接绕过工具注册、结果校验或风险确认。
- 实施时只提交本需求相关文件，保留当前工作区已有配送单发货、页面及其他用户改动。
