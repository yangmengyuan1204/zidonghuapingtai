# DeepSeek 数据智能体全中文展示设计

## 目标

DeepSeek 数据智能体的目标合同、实时执行过程、纠偏信息、权限暂停、成功/失败结果以及测试记录汇总全部使用中文业务文案，不向普通用户展示代码字段名、工具名、节点枚举或状态枚举。

用户主动展开“查看原始日志”时仍保留未经修改的原始 JSON，便于技术排查。

## 范围

本次只调整前端展示和对应测试，不修改后端接口、数据库、执行合同或数据脚本：

- `static/data-factory-agent.js`：集中维护数据智能体中文映射和专用渲染函数。
- `static/app.js`：数据智能体测试记录改用专用中文渲染，其他脚本保持现状。
- `tests/test_data_factory_agent.py`：增加中文展示契约回归测试。

## 中文展示层

`data-factory-agent.js` 维护以下集中映射：

- 字段：商品数量、购买数量、价格、运费、订单号、问题产品编号等。
- 节点：订单待付款、待拍下、采购待财务付款、上架入库、配送单报价等。
- 工具：创建并推进订单、查询订单状态、提出并处理问题产品等。
- 事件：目标理解、合同确认、执行决策、工具结果、实际校验、操作完成、权限暂停等。
- 枚举值：操作类型、价格口径、退款模式、支付方式、执行状态和布尔值。

展示函数不得使用代码字段名或枚举值作为用户界面的兜底文案。未知内容只能归入“其他执行信息”或隐藏。

## 页面数据流

智能体弹窗按以下顺序展示：

1. 用户原始要求。
2. 识别后的目标合同。
3. 有序执行操作。
4. 实时执行过程。
5. 自动纠偏和采用的默认值。
6. 最终业务结果。
7. 折叠的原始日志（仅测试记录页）。

最终结果按业务对象分组，优先展示：

- 执行结论和中文原因。
- 订单号、配送单号、问题产品编号、测试记录编号。
- 实际完成状态和当前业务节点。
- 商品种类、购买数量、执行单价、商品金额。
- 问题产品数量、单价和国内运费的处理前后值。
- 暂停或失败时的中文下一步建议。

## 值格式规则

- 已知字段和枚举值必须转换为中文。
- 布尔值显示“是”或“否”。
- 空值根据语义显示“未产生”或“保持原值”。
- 数组和嵌套对象按业务分组展示，不直接输出 JSON。
- 订单号、客户 ID、问题产品 ID 等业务编号保留原值。
- 原始代码字段只能出现在用户主动展开的“查看原始日志”中。

## 测试记录兼容

`app.js` 在日志中的 `script` 为“DeepSeek数据智能体”时，调用 `window.DataFactoryAgent` 提供的专用记录渲染函数。其他数据脚本继续使用现有通用汇总渲染逻辑。

如果专用渲染函数不可用，页面显示“数据智能体结果暂时无法展示”，不回退到包含代码字段的通用结果。

## 测试与验收

自动测试检查普通展示中不得出现以下类型的代码值：

- 字段名：`order_item_num`、`target_node`、`offer_price`、`operation_results`、`current_node`、`problem_goods_ids`。
- 工具名：`run_full_flow`、`inspect_order_state`、`process_problem_goods`。
- 节点和状态枚举：`order_offered`、`pending_purchase`、`purchase_wait_pay`、`succeeded`。

同时确认：

- 对应中文文案存在且语义准确。
- 未知字段不会通过兜底直接显示原名称。
- 数据智能体测试记录使用专用中文渲染。
- 折叠的原始日志仍保留原始 JSON。
- JavaScript 语法检查及数据智能体相关回归测试通过。

验收样本使用记录 805、823、824 的既有日志，只读覆盖历史成功、问题产品完成和续跑暂停，不执行业务操作。
