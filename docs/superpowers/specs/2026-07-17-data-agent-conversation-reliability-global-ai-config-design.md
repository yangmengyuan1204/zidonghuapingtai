# DeepSeek 数据智能体会话可靠性与全局 AI 配置设计

## 1. 背景与问题定位

用户近期多次创建数据智能体任务，在首次识别不完整后补充说明，但智能体仍不能稳定合并上下文，表现为重复追问、一次补充后直接失败、明确的“全部退款”仍被要求解释 option，以及失败会话难以通过执行记录追踪。

服务器访问记录显示，最近三个失败会话均只调用了创建会话和一次消息补充接口，没有进入确认和业务工具执行阶段。当前实现的主要问题如下：

- 同一字段第二次进入澄清就会被判定为阻塞。首次问题已经计数为一次，因此用户只获得一次补充机会。
- 每轮重新把全部对话交给模型生成完整目标，缺少字段级状态和增量合并。新回复可能覆盖已正确内容，也可能继续保留旧的错误约束。
- 后端只对少量 option 信息维护状态，价格、数量、目标节点、问题产品退款等字段没有统一的“最新明确说明优先”机制。
- 明确自然语言仍过度依赖模型解释，后端没有充分使用确定性业务规则。
- 确认前失败的分析过程没有持久化到执行记录，无法通过任务 ID 还原模型输入、输出、纠偏和失败原因。
- 页面加载与弹窗状态耦合，连续轮询或执行时可能一直遮挡内容，用户看不到当前节点。
- 平台多个模块存在 AI 配置入口，但实际写入同一份配置，容易被误认为各模块可以独立设置；保存空密钥还存在误清除原密钥的风险。

## 2. 设计目标

- 用户首次描述和后续补充形成一份持续演进的合同，不因再次调用模型而从头推翻。
- 后续消息只修改有明确证据支持的字段，未提及字段保持原值。
- 对订单状态、数量、价格口径、全部退款等明确表达进行确定性识别；只有真正缺失或冲突的信息才追问。
- 一次集中展示所有待确认字段，减少来回对话；不会因为同一字段第二次未解决就机械失败。
- 所有用户原话、识别结果、字段变更、纠偏、待确认项和失败原因均可通过任务记录审查。
- 执行过程持续展示当前步骤，加载层不遮挡节点和日志。
- 全平台只保留一个全局 AI 配置入口，各 AI 模块共享 API 地址、密钥和模型。
- 不修改数据库结构，不删除现有业务流程，不提交或推送代码。

## 3. 会话状态模型

### 3.1 字段级意图状态

会话不再只保存模型最后一次返回的完整目标，而是维护字段级状态：

- `resolved_fields`：已经确定的业务字段及其规范化值。
- `pending_fields`：仍缺失、歧义或相互冲突的字段。
- `evidence`：每个字段对应的用户原文、消息序号和识别来源。
- `revisions`：每次用户补充造成的字段变更记录。
- `operations`：按原话顺序排列的订单推进、配送单推进、问题产品等操作。
- `unhandled_requests`：后端已知但尚未进入操作合同的请求。

这些状态作为现有会话 JSON 的扩展字段保存，继续兼容当前 `goal.variables`、`target_node`、确认接口和执行接口。

### 3.2 每轮消息的增量合并

新消息按以下顺序处理：

1. 对最新一条用户消息执行确定性提取，得到字段补丁。
2. 调用模型识别该消息对现有合同的补充、修改或撤销，而不是重新生成整个目标。
3. 后端校验模型补丁，只接受有最新原文证据的变更。
4. 将补丁合并到现有字段状态；最新明确说明覆盖旧值，未提及字段保持不变。
5. 重新运行跨字段约束校验，生成统一的待确认项、合同摘要和可执行状态。

当用户说“不是 A，是 B”“其他不变”“全部都退”等表达时，系统记录为明确修订，不要求用户重新描述完整任务。

### 3.3 澄清策略

- 删除“同一字段第二次澄清就阻塞”的机械限制。
- 所有待确认字段合并到一条中文问题中展示，并给出系统当前理解。
- 用户可以直接用自然语言回答，不要求理解 `option`、字段名或内部代码值。
- 明确表达由后端直接落入合同，不再让模型重复询问。
- 只有业务信息仍然缺失、前后明确矛盾、超出支持范围或存在权限/金额风险时才继续澄清或暂停。
- 达到安全轮次上限时保留完整会话状态并说明尚缺字段，不将任务错误标记为执行失败。

## 4. 确定性语义与合同规则

继续保留已实现的状态、价格和多操作规则，并补充会话增量识别：

- “待付款、待支付、付款前”在新订单语境映射到订单待付款；“已付款、支付完成”映射到订单已付款。
- “两个商品”表示商品种类数；“每个数量 2、每种买 2 件”表示每种购买数量。
- “总价、商品总价、合计、一共”表示商品金额合计；“每件、每个、单价”表示单价。
- 只有“价格 1000”而无口径时才追问总价还是单价。
- “全部商品金额都退、全部数量退款”表示剩余可处理商品数量全部退款。
- “国内运费也全部退”表示问题处理后的国内运费为零。
- “商品金额和国内运费都退”必须同时生成数量退款和运费退款约束，不能只处理其中一个。
- “其他不变”禁止注入新的商品数、数量、价格或客户默认值。
- 多步骤指令必须形成有序操作列表，任何已知动作都不能被 assumptions 或摘要静默忽略。

合同摘要始终由后端依据最终字段状态重新生成，前端只展示中文业务名称和值，不展示代码字段名或枚举值。

## 5. 执行与验证

### 5.1 执行前

- 只有 `pending_fields` 和 `unhandled_requests` 均为空时才能确认执行。
- 确认页面展示操作顺序、数量、价格、退款前后值、默认项和风险提示。
- 用户编辑合同字段时生成一次明确修订，并重新执行约束校验。

### 5.2 执行中

- 会话记录 `current_operation_index`、当前中文步骤、开始时间和最近一次进度。
- 前端首次提交只在请求建立阶段显示局部加载状态；进入后台执行后立即恢复页面交互。
- 进度区域固定可见，展示“正在创建订单”“正在推进到待拍下”“正在处理问题产品”“正在校验结果”等节点。
- 轮询请求互斥，上一轮未结束时不再发起下一轮；页面关闭弹窗不会中断后台任务。

### 5.3 执行后

- 订单状态、商品种类数、每种数量、逐商品单价、商品金额、问题产品状态、剩余数量和国内运费均以真实查询结果校验。
- “全部商品金额和国内运费退款”只有在退款数量符合合同且国内运费为零时才成功。
- 权限暂停、数据未同步、查询不到价格或任一操作未完成时均不能记录成功。
- 多操作任务按操作逐项记录结果；恢复执行时跳过已验证成功的项目，避免重复造数。

## 6. 分析记录与可审计性

不新增数据库表或字段，复用现有测试记录结构增加 `data_agent_analysis` 类型记录。每次首次识别和用户补充均记录：

- 会话 ID、消息轮次和脱敏后的用户原话。
- 调用模型时使用的模型名称和请求阶段。
- 模型候选补丁、确定性提取结果和最终合并结果。
- 被后端拒绝或纠正的字段及原因。
- 当前待确认字段、未覆盖请求和会话状态。
- 异常分类及中文错误摘要。

API Key、认证头、Cookie 和其他密钥不得写入记录。记录写入失败不能阻塞主流程，但必须写服务器错误日志。

## 7. 全局 AI 配置

### 7.1 唯一入口

- 删除数据智能体、功能测试、需求校验等模块页面内的 AI 配置按钮及专属事件绑定。
- 在平台顶部导航栏右上角增加唯一“全局 AI 配置”入口，仅管理员可见。
- 所有模块继续读取同一份 `AiConfig`，不提供模块级 API 地址、密钥或模型覆盖。
- 模块自身提示词、业务规则和生成参数仍由各模块维护，不属于连接配置。

### 7.2 配置交互

配置项包括服务商、API 地址、模型和 API Key。窗口明确提示“修改后影响全平台后续 AI 任务”，并展示当前使用模型。

- API Key 留空表示保留现有密钥，不允许因只改模型而清空密钥。
- 提供“测试连接”操作，只验证当前表单中的配置，不落库。
- 测试结果区分认证失败、模型不可用、网络/代理失败、超时和返回格式异常。
- 保存成功后，各模块下一次 AI 调用使用新配置；已经运行中的任务保持启动时的配置快照，不在中途切换模型。

后端保留统一 `/api/ai-config` 接口，并增加受管理员权限保护的连接测试接口。审查并移除页面级配置覆盖、重复表单封装或本地存储配置；不存在的独立配置不做无意义重构。

## 8. 页面兼容与缓存

- 使用现有顶部导航和弹窗样式，避免新增前端框架。
- 数据智能体合同、进度、失败原因和成功结果全部使用中文业务文案。
- 删除旧模块按钮后同步清理对应元素查询和事件绑定，避免 JavaScript 空节点异常。
- 更新静态资源版本号，确保浏览器加载新页面逻辑。
- 现有会话、确认、执行和权限恢复接口保持兼容；新增字段均为向后兼容的只读或可选字段。

## 9. 错误处理

- 模型调用失败：保留现有字段状态，允许重试，不清空用户已确认内容。
- 模型返回非法结构：记录脱敏原始摘要，使用确定性结果；不足时集中追问。
- 用户修订导致冲突：标出冲突字段和当前理解，不执行相关业务工具。
- 业务工具失败：停止当前操作并记录实际结果，已完成操作保持幂等状态。
- 页面轮询失败：显示最近成功进度和重试按钮，不使用永久遮罩。
- 全局配置测试失败：不保存表单，不影响当前有效配置。

## 10. 测试与验收

### 10.1 自动化测试

- 字段补丁合并、最新明确证据优先和未提及字段保持。
- 同一字段多轮补充不会在第二次机械阻塞。
- 一次集中提出多个待确认字段。
- 订单状态、数量、总价/单价和问题产品退款确定性规则。
- “商品金额和国内运费全部退”同时生成并验证两类约束。
- 多操作顺序、未覆盖操作拦截、恢复幂等和真实结果校验。
- 分析记录写入、敏感字段脱敏和失败会话可追踪。
- 全局配置管理员权限、空 API Key 保留、连接测试不落库。
- 旧模块按钮删除、顶部入口权限及前端空节点兼容。
- 进度轮询互斥、加载状态释放和错误重试。

### 10.2 自然语言识别矩阵

使用当前真实模型，对不少于 20 条贴近用户口吻的指令连续运行三轮，仅进行目标理解，不执行业务。覆盖：

- 新建与续跑订单。
- 待付款、已付款、待拍下、采购待财务付款等状态。
- 商品种类、每种数量、商品总价、统一单价和逐商品单价。
- 首次描述不完整后的一次或多次自然语言修订。
- 全部退款、部分退款、保留运费、全部国内运费退款。
- 商品金额与运费组合处理、多商品和多步骤操作。
- 明确指令、歧义指令、矛盾指令和不支持请求。

明确指令必须形成完整合同；歧义或冲突必须指出具体字段；任何已知操作不得静默遗漏。

### 10.3 真实低风险体验

识别矩阵通过后，在测试环境创建少量低金额数据，覆盖订单推进、续跑保持和问题产品全退。每个任务均查询真实业务数据校验，测试记录保留，不删除数据，不对历史任务重复处理。

### 10.4 工程检查

- 使用项目 `.venv\\Scripts\\python.exe` 运行相关测试。
- 执行 JavaScript 语法检查和静态资源引用检查。
- 按用户要求验证页面时才启动浏览器；默认不保留截图、报告或临时文件。
- 完成后检查 `git status --short` 和 `git diff --stat`，不提交、不推送。

## 11. 修改范围

预计涉及以下现有模块，具体文件清单在实施计划阶段根据代码审查确定：

- 数据智能体会话理解与执行服务。
- 数据智能体路由和请求/响应结构。
- 数据智能体页面交互与进度展示。
- 全局 AI 配置路由、共享配置弹窗和顶部导航。
- 数据智能体与 AI 配置相关测试。

不修改数据库结构、数据脚本业务流程、密钥文件、启动脚本和无关模块，不覆盖工作区已有改动。

## 12. 验收标准

- 用户补充后，已正确字段保持不变，明确修订准确覆盖旧值。
- 不再出现“补充一次仍不理解就直接失败”的固定行为。
- 用户无需理解 option 或代码字段名即可完成任务。
- “全部商品金额和国内运费退款”不会只处理国内运费。
- 明确任务尽量一次确认；确需追问时一次列全缺失字段。
- 失败会话可以通过任务或会话 ID 查看完整脱敏分析链路。
- 执行期间始终可以看到当前中文节点，不出现永久弹窗或永久加载。
- 平台只有顶部右上角一个“全局 AI 配置”入口，各模块不再显示独立配置按钮。
- 切换全局模型后影响后续全平台 AI 任务，但不会清空密钥或中途改变运行中任务。
- 自动化测试、三轮自然语言识别矩阵和低风险真实体验全部通过后才交付。
