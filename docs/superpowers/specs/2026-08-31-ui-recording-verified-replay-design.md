# UI 自动化验证式录制与双轮回放设计

## 1. 背景

现有 UI 录制能力已经支持元素指纹、候选定位器评分、唯一性校验、干净会话预检、定位记忆和安全写回，但真实使用中的录制后回放成功率仍未明显提高。

根因并非单一定位器质量问题，而是录制结果缺少以下信息：

- 元素所在的弹窗、表单、表格行、卡片或菜单等业务上下文。
- 操作执行前页面应满足的状态。
- 操作执行后应产生的可观察结果。
- SPA、遮罩层、动画、延迟渲染等页面时序。
- iframe、新标签页和复杂组件的稳定上下文。
- 数据重置后动态业务值与录制步骤之间的关联。

继续增加 fallback locator 只能减少少量定位失败，无法同时解决错误页面状态、动作未生效、重复提交和复杂控件等问题。本次改造将录制机制升级为“验证式录制”。

## 2. 目标

录制和保存流程升级为：

```text
录制元素与动作结果
  → 编译语义化步骤
  → 重置测试数据
  → 第一轮修复验证
  → 必要时人工重新选点
  → 重置测试数据
  → 第二轮冻结验证
  → 保存为 active
```

验收目标：

- 经过双轮验证后保存的用例，后续干净回放成功率不低于 97%。
- 错误点击率为 0。
- 危险操作不会因为等待超时而盲目重复执行。
- 每次失败都能区分数据、登录、环境、上下文、定位、交互和业务断言问题。
- 旧格式步骤和现有 API 路径保持兼容。

## 3. 非目标

首期不覆盖：

- Canvas 内部元素定位。
- 拖拽、文件上传和复杂富文本编辑器。
- 无人工确认的视觉坐标点击。
- 直接修改被测系统数据库进行数据重置。
- 强制要求被测系统增加 `data-testid`。

## 4. 核心原则

### 4.1 从定位器录制升级为目标描述

新步骤继续保留兼容字段：

- `locator`
- `fallback_locators`
- `locator_profile`

新增：

- `target_profile`：描述页面、frame、容器和目标元素。
- `effect_profile`：描述动作执行后必须发生的结果。
- `retry_policy`：描述当前动作是否允许自动重试。

执行器不再无条件优先尝试旧主定位器，而是对当前页面中的全部候选进行统一解析、评分和安全检查。

### 4.2 状态驱动而非固定等待

每个动作包含前置条件和后置结果。执行器必须等待控件稳定、可用、无遮挡，并在执行后确认录制时观察到的结果已经发生。

### 4.3 双轮验证

第一轮允许重新选点和重新编译；第二轮冻结编译结果，禁止 AI 自愈和自动写回。只有两轮均从数据重置开始并完整通过，才能保存为 `active`。

### 4.4 安全失败

匹配不唯一、置信度不足、候选差距过小、动作结果不明确或危险操作可能重复执行时，必须停止并进入人工检查，不允许通过 `.first`、坐标点击或无条件重试继续执行。

## 5. 目标描述模型

### 5.1 页面上下文

`target_profile.page` 包含：

- URL 模式及可忽略动态参数。
- 页面标题特征。
- 标签页来源步骤和 opener 关系。
- 页面创建顺序，仅作为低权重辅助信息。

运行时通过页面身份解析标签页，不再只依赖容易变化的 `page_index`。

### 5.2 iframe 上下文

`target_profile.frame_chain` 逐层记录：

- frame 名称。
- frame URL 模式。
- frame 元素的稳定属性。
- frame 邻近标题或容器特征。

每一层必须唯一解析，支持多层 iframe；无法唯一解析时安全停止。

### 5.3 容器上下文

`target_profile.scope_chain` 按由外到内记录目标所属范围，例如：

- dialog 或 drawer。
- form。
- table 和目标 row。
- card。
- menu 或 dropdown panel。

表格中的重复按钮必须先解析目标行，再在行内解析按钮。例如“订单号为 `${reset.order_no}` 的表格行中的删除按钮”，不能直接使用页面级“删除”文本。

### 5.4 元素语义

记录：

- tag、type、role。
- accessible name、label、placeholder。
- `data-testid`、`data-test`、name 等稳定属性。
- 稳定 class 片段、href 路由特征和业务属性。
- 邻近字段标题、表头、前后控件文字。
- 是否可点击、可输入、可勾选或可选择。

不得保存密码、Token 或其他敏感输入值。

## 6. 目标解析与评分

运行时解析顺序不是简单 fallback 顺序，而是统一候选池：

1. `data-testid`、`data-test` 等稳定标识。
2. 限定容器内的精确 role 和 accessible name。
3. label、placeholder、name 与元素类型的组合。
4. 表格行、弹窗、表单等上下文约束后的属性和文本组合。
5. 确定性 DOM 指纹相似度。
6. 项目级历史成功定位记忆。
7. AI 或视觉生成的建议候选。

执行动作前必须同时满足：

- 唯一匹配。
- 可见、可用且未被遮挡。
- 元素位置和尺寸在短暂稳定窗口内不再变化。
- 元素类型与动作兼容。
- 所属页面、frame 和容器上下文正确。
- 第一候选达到最低置信度，且与第二候选存在足够分差。

AI 和视觉能力只能生成候选或辅助用户重新选点，不得在置信度不足时直接操作。

## 7. 动作结果模型

录制时在动作前后采集轻量页面状态，自动推断 `effect_profile`。支持：

- URL 或路由变化。
- 新标签页出现。
- dialog、drawer 或下拉面板出现、关闭。
- 目标元素出现、消失、启用或禁用。
- 输入值、勾选状态和选中项变化。
- 表格新增、删除或更新目标行。
- 成功或失败提示出现。
- 页面进入加载状态并最终恢复。
- 与动作关联的指定网络请求完成。

每个动作至少需要一个可验证结果。纯聚焦、无业务结果的动作可由编译器合并或忽略。

### 7.1 防止重复提交

动作等待超时后，先重新检查 `effect_profile`：

- 结果已经发生：动作视为成功，不再次点击。
- 结果未发生且动作被标记为可安全重试：重新解析目标后重试一次。
- 提交、删除、支付等危险动作：禁止自动重复，进入人工检查。

## 8. 复杂控件适配

新增独立控件适配层，首期覆盖：

- 原生输入、下拉、checkbox 和 radio。
- Element Plus 常用下拉、日期、弹窗和表格。
- Ant Design 常用下拉、日期、弹窗和表格。
- 自定义弹窗和 drawer。
- iframe。
- 新标签页。
- SPA 路由切换和延迟渲染。

适配器负责定义目标解析、正确交互方式和结果检测，不能把所有组件降级成普通 CSS 点击。

## 9. 数据重置

### 9.1 配置方式

每个 UI 项目选择一个平台现有数据脚本作为重置脚本。新增独立配置表 `ui_record_project_config`，至少包含：

- `project_id`，唯一。
- `reset_script_key`。
- `reset_env_id`，必须属于当前项目。
- `reset_variables_json`。
- `verification_rounds`，首期固定为 2。
- `max_repair_attempts`。
- 创建和更新时间。

不修改现有 `Project` 和 `UiCase` 字段。

### 9.2 执行规则

- 每一轮浏览器回放开始前先运行重置脚本。
- 重置失败时不启动该轮浏览器执行。
- 重置脚本通过现有数据脚本业务入口执行，不由 UI 执行器直接调用路由或操作业务数据库。
- 重置结果必须保存到当轮运行上下文，不写入正式用例中的敏感字段。

### 9.3 动态变量

重置脚本返回的业务值作为 `${reset.xxx}` 变量提供给：

- 输入值。
- URL。
- 业务断言。
- 表格行、卡片和其他目标上下文。

每轮开始时重新解析变量，避免订单号、商品名或账号等动态数据变化造成定位失败。

## 10. 双轮验证与人工修复

### 10.1 第一轮修复验证

1. 执行项目配置的数据重置脚本。
2. 创建全新浏览器上下文并恢复安全登录状态。
3. 从起始 URL 执行完整步骤。
4. 每步验证目标、前置状态和动作结果。
5. 失败时暂停并保存页面、截图、DOM 上下文、候选和失败分类。

### 10.2 重新选点

V3 页面提供“重新选点”。启用后，用户在暂停的录制浏览器中直接点击正确元素。系统重新采集该元素的完整 `target_profile`，只更新当前录制会话中的临时编译结果。

重新选点后必须重新执行数据重置并从第一步开始验证，不能从失败步骤继续，以防前序业务状态已经发生变化。

### 10.3 第二轮冻结验证

第一轮通过后：

1. 再次执行数据重置。
2. 创建新的浏览器上下文。
3. 冻结第一轮的步骤和目标描述。
4. 禁止 AI 自愈、定位记忆自动写回和人工中途修改。
5. 完整执行并验证最终业务断言。

第二轮失败后返回修复流程；修复后两轮均需重新执行。

### 10.4 保存状态

- 两轮均完整通过且无高风险步骤：`active`。
- 用户中止、验证失败或危险操作结果不明确：`draft`。
- 保存时服务端校验预检运行与当前步骤快照完全一致。
- 正式步骤发生自动写回前仍需创建 revision。

## 11. 错误分类

统一分类为：

- `reset_error`：数据重置失败。
- `auth_error`：登录状态或权限失败。
- `environment_error`：浏览器、网络或被测环境异常。
- `page_context_error`：页面、标签页或 iframe 上下文错误。
- `locator_error`：目标无法唯一、安全解析。
- `interaction_error`：目标被遮挡、不可用或交互方式错误。
- `effect_error`：动作未产生预期结果。
- `assertion_error`：最终业务断言失败。

失败报告必须包含具体步骤、实际 URL、截图、候选、评分理由和建议操作。

## 12. API 与兼容性

保留现有：

- `POST /api/ui-record/sessions/{session_id}/preflight`
- `GET /api/ui-record/preflights/{run_id}`
- `POST /api/ui-record/sessions/{session_id}/save`

现有预检接口升级为双轮验证编排，报告中增加：

- 当前轮次和总轮次。
- 数据重置状态及非敏感变量键名。
- 编译、执行、结果验证和冻结验证状态。
- 当前修复次数。

新增接口：

- `GET /api/ui-record/projects/{project_id}/config`：读取项目录制验证配置。
- `PUT /api/ui-record/projects/{project_id}/config`：保存重置脚本及验证参数。
- `POST /api/ui-record/preflights/{run_id}/steps/{step_index}/repick/start`：让暂停的录制浏览器进入当前步骤重新选点状态。
- `POST /api/ui-record/preflights/{run_id}/restart`：应用临时修复后，从数据重置开始重新执行双轮验证。

重新选点结果通过当前录制会话已有的浏览器事件通道回传，并由预检运行绑定到指定步骤。旧客户端不传重置配置时仍可执行一次兼容预检，但不能因此保存为新的双轮验证 `active` 用例。

## 13. V3 页面

录制前增加数据重置脚本选择与参数配置。

“停止并检查”后的验证面板展示：

- 编译状态。
- 当前轮次。
- 数据重置状态。
- 当前步骤和总体进度。
- 原目标、实际候选和评分原因。
- 动作预期结果与实际结果。
- 失败截图和 URL。
- 重新选点。
- 从头重新验证。
- 保存待修复草稿。

用例列表继续区分 `active` 和 `draft`。用例详情保留 revision 和回滚入口。

## 14. 存储设计

- `target_profile`、`effect_profile` 和 `retry_policy`保存在现有步骤 JSON 中。
- 双轮验证、修复过程和截图索引复用 `ui_record_preflight.report_json`。
- `ui_record_preflight.steps_json`保存本次验证的冻结步骤快照。
- 仅新增独立 `ui_record_project_config` 表，不修改现有核心模型字段。
- 旧步骤缺少新增字段时继续使用现有执行逻辑。

## 15. 测试设计

### 15.1 后端单元测试

- 重复按钮文本必须通过弹窗、表格行或表单上下文唯一化。
- 动态 ID 不成为高优先级候选。
- 候选分差不足时安全失败。
- 元素被遮挡、移动或类型不兼容时不执行。
- 多层 iframe 和新标签页身份解析。
- 动作结果推断和等待。
- 危险动作超时后不重复执行。
- 无 AI 配置时确定性策略仍可工作。

### 15.2 验证编排测试

- 每轮开始前执行数据重置。
- 数据重置失败后不启动浏览器。
- `${reset.xxx}`每轮重新解析。
- 第一轮允许临时修复。
- 第二轮冻结步骤并禁止自愈。
- 任一轮失败时只能保存为 `draft`。
- 两轮成功且步骤快照一致时保存为 `active`。

### 15.3 前端契约测试

- 重置脚本配置。
- 双轮进度与轮询清理。
- 失败截图和结果展示。
- 重新选点状态切换。
- 草稿保存和 active 状态。
- 旧录制流程兼容。

### 15.4 真实业务验收

使用至少 30 条真实流程，每条先完成双轮录制验证，再独立干净执行 3 次：

- 后续干净回放成功率不低于 97%。
- 错误点击率为 0。
- 所有失败均能定位到具体步骤和失败类别。
- 危险操作不存在重复提交。

真实验收需要测试账号、可用登录状态、数据重置脚本和单独的浏览器操作确认。

## 16. 实施边界

本功能涉及录制、执行器、数据重置、数据库和 V3 页面，无法限制为 1–2 个文件。实施时按以下边界拆分：

- 目标描述和评分服务。
- 动作结果检测服务。
- 数据重置适配服务。
- 双轮验证编排服务。
- 复杂控件适配层。
- 路由和持久化。
- V3 独立组件和 API 模块。

不进行无关重构，不修改现有数据脚本的入参、返回值或执行流程；通过统一适配器调用已选择的数据脚本。

## 17. 风险与控制

- **录制保存时间增加**：页面展示明确轮次和步骤进度。
- **数据重置脚本不幂等**：验证前先检查脚本执行结果，失败立即停止。
- **动作结果推断错误**：允许用户调整最终断言；危险操作结果不明确时保存为草稿。
- **复杂组件差异**：首期只覆盖已声明的原生、Element Plus 和 Ant Design 常用组件。
- **动态变量泄漏**：报告仅展示允许的变量键和值摘要，敏感字段始终脱敏。
- **人工修复造成偶然通过**：第二轮冻结验证，禁止任何运行时自愈和写回。
