# 系统回归——日本站金额与问题产品回归设计

日期：2026-07-29  
状态：设计已确认，待用户复审与实施计划  
范围：首版仅日本站；legacy 独立业务模块；后续可扩展其他项目

## 1. 目标

新增顶级菜单“系统回归”，首版提供日本站支付金额与问题产品回归。测试人员只填写普通表单参数，可单条执行或批量勾选执行。系统自动造单、执行业务流程，并对比独立预期金额、后台预览金额和真实资金流水。

核心目标：

- 系统回归与数据工厂分离，按业务项目组织，日本站作为首个项目。
- 系统预置用例可编辑、保存、复制、启停、排序和恢复默认。
- 批量执行和单条执行共用同一套用例与执行器。
- 每条用例创建独立订单，统一批次号，失败后继续后续用例。
- 问题产品用例按后端真实计算分支设计，不做无效笛卡尔积。
- 实际支付或问题产品调整产生的真实出入金，与报价、独立预期及后台预览核对。
- 原数据工厂和已有数据脚本接口、行为保持兼容。

## 2. 已确认业务规则

### 2.1 金额与资金渠道

- 每个金额字段内部保存数值、币种和来源；页面使用普通输入框，不要求填写 JSON。
- 默认采购侧人民币，客户报价及客户账单日元，允许用例级覆盖。
- 汇率只能来自订单、预览账单或其他业务证据，禁止用请求参数冒充证据。
- 人民币换算日元后四舍五入到整数。
- 独立预期与后台预览、后台预览与真实流水的差值均不超过 1 日元时通过；达到 2 日元失败。
- 余额支付以客户余额新增扣款为实际证据。
- 银行支付以唯一匹配且完成财务确认的银行流水为实际证据。
- 无论原订单使用余额还是银行支付，问题产品产生的退款或补款都只写入客户余额账单。
- 退款必须是客户余额入账，补款必须是客户余额出账，方向错误直接失败。
- 零金额场景必须在完整等待窗口内没有匹配的客户流水。

### 2.2 问题产品后端真实公式

根据 `ProblemGoodsService.php` 的 `g_deal` 和 `optionChangeDetail`：

```text
新商品金额 = 修改后整番数量 × 修改后单价
商品差额 = 新商品金额 - 原整番数量 × 原整番单价
总人民币差额 = 商品差额 + 单条采购运费差额 + 手续费差额 + OPTION 差额
客户账单日元 = round(-总人民币差额 × 业务汇率)
```

其中：

- 问题类型主要是业务分类，不直接决定金额方向。
- 单价是整番共享字段，运费差额按单条采购记录计算。
- 商品免费规则下不计算商品金额差额。
- 手续费只根据商品金额差额计算，不跟国内运费或 OPTION 变化。
- 商品金额减少时，只有选择“多退少补”、客户实际支付过手续费且未使用手续费减免券，才退手续费。
- 商品金额增加时正常补收手续费；使用手续费减免券时不补收。
- OPTION 支持固定金额和百分比；已存在 OPTION 不允许切换计价类型。
- 自动 OPTION 不允许商品数量增加、OPTION 数量超过商品数或多个百分比 OPTION。
- 检品 OPTION 自动计算时，已完成检品数量不退款。
- 净差额为零时不应生成客户账单。
- 退款人民币金额达到或超过 500 元，需要部长账号操作。

## 3. 信息架构与页面

```text
系统回归
└─ 日本站
   ├─ 支付金额
   ├─ 问题产品金额
   ├─ OPTION 计算
   ├─ 问题产品流程
   ├─ 业务规则拦截
   ├─ 自定义用例
   └─ 执行记录
```

首版采用 legacy 独立模块上线，后端 API、路由标识和页面状态按未来 Vue 迁移设计。当前 Frontend V2 尚处于基础组件阶段，不提前进入 Vue 业务页，也不打断现有迁移计划。

页面采用三栏布局：

- 左侧：项目与用例分类树。
- 中间：用例表格，支持搜索、筛选、单选、当前页全选、分类全选、全部选择、批量执行、复制、启停和恢复默认。
- 右侧：当前用例参数抽屉，编辑整单、单番、费用、OPTION、支付、配送和问题产品参数。
- 顶部：默认项目、环境和测试客户，可在本次批次临时覆盖。

系统用例不可删除，可恢复默认；自定义用例由复制系统用例产生，可以删除。执行前展示预计创建订单数和预计时长，并二次确认测试数据会保留。

## 4. 表单参数模型

页面不提供 JSON 编辑框。结构化 JSON 仅用于后端存储和接口传输，由前端普通控件自动组装。

### 4.1 用例与执行设置

- 用例编号、名称、项目、分类、标签、排序、启用状态。
- 预期成功、预期业务拦截或等待人工处理。
- 超时时间、流水等待窗口、允许日元差值。
- 用例版本、修改人、修改时间、恢复默认。

### 4.2 环境与账号

- 默认 Project、Env、客户账号。
- 后台业务、采购、财务账号。
- 大额退款默认部长账号固定选择项目内“沈文妮”账号配置。
- 批次级覆盖和单条用例覆盖。
- 临时账号密码使用密码输入框，只保留在本次运行内存中，不落库、不写日志和报告。

### 4.3 整单默认值

- 店铺数量、商品番数、每番默认数量。
- 默认采购价、确认价、报价价。
- 默认采购运费、确认国内运费、报价国内运费。
- 商品费用规则、手续费率。
- 其他费用金额、其他费用名义。
- 预计国际物流费、优惠金额、手续费减免券、配送代金券。
- 商品、国内运费、手续费、附加服务费和其他费用所属支付阶段。

### 4.4 单番覆盖

每个番号独立编辑：商品平台、商品 ID、SKU、店铺、购买/确认/报价数量、采购/确认/报价单价、采购/确认/报价中国国内运费、重量、长宽高、手续费率覆盖、问题产品开关和 OPTION 列表。

整单默认值同步到未覆盖的单番；单番已修改字段保留覆盖状态，并可恢复继承。

### 4.5 OPTION

OPTION 以可增删表格行呈现：ID、名称、日文名称、固定金额或百分比、价格或比例、数量、是否选中、是否自动计算、已完成服务数和已检品数。

联动规则：

- 已有 OPTION 不允许切换计价类型。
- 商品数量增加、OPTION 数量超过商品数或多个百分比 OPTION 时，自动禁用系统自动计算并说明原因。
- 检品 OPTION 单独展示已完成数量保护的计算明细。
- 允许提交空 OPTION 列表表示全部取消。

### 4.6 支付、配送和问题产品

- 支付：余额/银行、全额/分批、首款比例与金额、尾款金额、费用所属阶段、财务确认和银行流水匹配。
- 配送：物流方式、人工物流费、合并付款、配送代金券、报价和实际取证。
- 问题产品：类型 1–10、提出数量、修改后数量/单价/单条采购运费、客户选择与回复、业务决策、手续费规则、OPTION 规则和新 OPTION。
- 采购处理：退货退款、换货、丢货重拍、少货补买、其他、仅退款，另含采购备注、补买记录、赔款单号、跳过采购、跳过配货、配货直接完成和最终配货确认。
- 拦截用例：预期错误码和一个或多个错误关键词使用普通输入框及可增删标签编辑。

## 5. 日本站预置矩阵

首版共 77 条：支付金额 10 条，问题产品成功路径 52 条，问题产品预期拦截 15 条。不是任意参数笛卡尔积；10 种问题类型各至少有一条完整流程，仅对有特殊后端分支的类型增加交叉。

### 5.1 支付金额（10）

1. 单番余额全额支付：报价日元与客户余额实际出账一致。
2. 单番银行全额支付：报价日元与已匹配且财务确认的银行入账一致。
3. 余额分批付款：首款与尾款合计等于整单应付金额。
4. 银行分批付款：两次确认流水合计等于整单应付金额。
5. 配送单余额支付：配送报价与客户余额实际出账一致。
6. 配送单银行支付：配送报价与已确认银行入账一致。
7. 多单番独立国内运费：每番运费正确汇总并参与报价。
8. 其他费用金额与名义：其他费用正确计入报价和实际出账。
9. 多 OPTION 混合：固定金额、百分比和数量分别正确计算。
10. 全费用混合订单：商品、国内运费、手续费、附加服务费、OPTION、其他费用、优惠和配送费用综合校验。

### 5.2 问题产品基础金额（12）

1. 客户原因：数量、单价、运费不变，零金额、无流水。
2. 少货：数量部分减少，商品差额退款。
3. 少货：数量全部减少至零，商品金额全部退款。
4. 单价变动：单价下调退款。
5. 单价变动：单价上调补款。
6. 运费变动：单条采购运费下调退款。
7. 运费变动：单条采购运费上调补款。
8. 不良且少货：数量减少、单价不变。
9. 不良且少货：数量减少、单价下调。
10. 不良：数量减少、单价上调，按净差额判定方向。
11. 其他：单价下调、运费上调，最终净退款。
12. 其他：单价上调、运费下调，最终净补款。

### 5.3 问题产品手续费（6）

1. 商品减少、已支付手续费、无券、多退少补。
2. 商品减少、已支付手续费、无券、已收不退。
3. 商品增加、无券，补收商品和手续费。
4. 商品减少、使用手续费减免券，不退手续费。
5. 商品增加、使用手续费减免券，不补收手续费。
6. 单番手续费率为零，手续费差额为零。

### 5.4 OPTION 按业务修改值（15）

- 固定金额：新增、删除、数量增加、数量减少、价格增加、价格减少。
- 百分比：新增、删除、数量增加、数量减少、比例提高、比例降低、商品单价变化引发金额联动。
- 组合：全部取消 OPTION；多个固定和百分比 OPTION 同时变化并核对净差额。

### 5.5 OPTION 系统自动计算（6）

1. 数量减少，固定 OPTION 自动减少。
2. 数量减少，百分比 OPTION 按剩余数量和商品价重算。
3. 商品单价下调，百分比 OPTION 联动。
4. 检品 OPTION 存在已完成检品数量，已完成部分不退款。
5. `auto_calculate=false` 的 OPTION 保持不变。
6. 商品和 OPTION 均不变，OPTION 差额为零。

### 5.6 综合净额（3）

1. 数量、单价、运费、手续费和多个 OPTION 综合后净退款。
2. 同样维度综合后净补款。
3. 正负分项完全相抵，预览为零且无客户流水。

综合用例必须同时验证每个分项和最终净额，避免分项错误后碰巧相抵。

### 5.7 十类问题产品流程（10）

1. 单价变动：接受处理、单价调整、仅退款。
2. 运费变动：接受处理、运费调整、仅退款。
3. 少货：接受处理、少货补买、配货确认。
4. 不良：换货、采购处理、配货确认。
5. 不良且少货：退货退款、配货确认。
6. OPTION 变动：OPTION 修改、其他采购处理。
7. 数量多了：满足权限前提、数量增加、余额补款。
8. 其他：客户自定义回复、其他采购处理。
9. 客户原因：已收不退，无资金流水。
10. 不良直接上架：标准采购处理，不使用受限的配货直接完成。

接受、交换、取消、废弃和其他客户回复分配到代表流程覆盖，不与金额分支全部交叉，因为源码中客户回复不参与金额公式。

### 5.8 预期拦截（15）

1. 分批付款尾款未完成时禁止业务决策。
2. 转寄订单禁止提出问题产品。
3. 采购处于待财务付款状态时禁止提出。
4. 同采购记录存在未完成问题产品时禁止重复提出。
5. 问题数量超过未上架数量时禁止提出。
6. 修改后数量小于已上架数量时禁止采购处理。
7. 普通账号把数量改得超过可入库数时权限拦截。
8. 数量增加却选择 OPTION 自动计算时拦截。
9. OPTION 数量超过商品数并选择自动计算时拦截。
10. 多个百分比 OPTION 使用自动计算时由脚本前置拦截。
11. 修改已有 OPTION 计价类型时由脚本前置拦截。
12. 同番存在多条采购记录时禁止修改预处理数据。
13. 退款达到或超过 500 元且非部长账号时暂停并切换账号。
14. 少货、不良或不良且少货已有交易号却跳过采购时，普通账号被拦截。
15. 非少货、不良或不良且少货类型使用配货直接完成时类型拦截。

## 6. 执行状态与批次行为

状态包括：`queued`、`running`、`waiting_account`、`passed`、`failed`、`blocked`、`stopped` 和 `cancelled`。

- 批量默认顺序执行，避免并发修改同一客户余额。
- 每条用例创建独立订单和问题产品，保存统一批次号。
- 执行开始时保存不可变参数快照；执行中修改用例不影响本批次。
- 单条失败或阻塞后继续其他用例。
- 停止批次只停止未开始用例，当前写操作完成状态核对后再停。
- 重跑创建新订单和新明细记录，并关联原执行记录。
- 预期拦截出现配置错误码或关键词时判定通过；未拦截或出现其他错误时失败。

## 7. 大额退款账号切换

金额预览发现人民币退款达到或超过 500 元时：

1. 自动读取项目内固定的沈文妮部长账号配置。
2. 自动登录成功后，查询问题产品状态与已有流水，从安全恢复点继续。
3. 自动登录失败或账号未配置时，当前用例进入 `waiting_account`。
4. 页面弹出账号和密码输入框；临时密码只存在本次运行内存。
5. 登录成功后可只恢复当前用例，或恢复本批次全部等待账号用例。
6. 恢复前必须查询状态和流水，禁止重新造单、重复提出问题产品、重复采购处理或重复退款。
7. 等待账号期间，批次中不需要该账号的用例可以继续。

## 8. 三方证据与通过规则

每条成功用例生成三套证据：

```text
独立预期计算金额 → 后台问题产品预览金额 → 客户余额或银行实际流水
```

- 支付用例按余额或已财务确认银行流水取证。
- 问题产品用例只按客户余额差集取证。
- 流水必须通过客户、订单号、番号、问题产品 ID、方向和时间窗口唯一匹配。
- 缺失流水、重复歧义、缺少汇率、方向错误或超过误差均失败。
- 请求参数和预览响应不能充当实际金额证据。

## 10. 数据模型

新增四张表：

- `system_regression_suite`：项目、默认环境、客户和角色账号、沈文妮账号、默认误差和超时。
- `system_regression_case`：用例定义、参数、预期规则、默认副本、版本、启用和排序。
- `system_regression_batch`：批次号、执行环境、状态统计、覆盖参数、执行时间和人工等待原因。
- `system_regression_case_run`：用例快照、状态、恢复点、业务编号、三方证据、金额差值和错误信息。

新表是系统回归事实源；同时向现有 `TestRecord` 写批次主记录和用例明细兼容记录。临时密码不进入任何表。

```text
POST   /api/system-regression/batches/{batch_id}/stop

POST   /api/system-regression/runs/{run_id}/resume-account
POST   /api/system-regression/runs/{run_id}/rerun
GET    /api/system-regression/runs/{run_id}
```

创建批次立即返回批次 ID，后台继续执行，避免长时间 HTTP 请求超时。页面轮询批次和用例状态。

服务重启后，`running` 记录进入状态核对：先查询订单、问题产品及资金流水，确认安全恢复点后继续；无法确认是否已发生资金写入时标记 `blocked`，禁止盲目重试。

## 12. 测试与验收

### 12.1 测试

- 金额算法：商品、运费、手续费、固定和百分比 OPTION、检品保护、综合净额、币种换算和误差边界。
- 77 条目录：10 条支付金额、52 条问题产品成功路径和 15 条预期拦截；验证参数合法性、问题类型覆盖、方向、恢复默认和复制。
- 取证：余额、银行、前后差集、唯一匹配、缺失和歧义。
- 批次：单条、批量、失败继续、停止、等待账号、账号恢复、服务重启和重跑。
- 安全：临时密码不落库、不写日志；网络不确定写操作不得直接重试。
- 接口与数据库：用例管理、批次、恢复、TestRecord 兼容和原数据脚本契约。
- 测试命令使用 `.venv\Scripts\python.exe`，默认不启动浏览器。

### 12.2 验收

- 顶级菜单为“系统回归”，日本站独立分类。
- 77 条日本站用例可以单选、分类全选和批量执行，其中问题产品用例 67 条。
- 所有参数使用输入框、下拉框、复选框和可增删表格，不要求填写 JSON。
- 整单费用、其他费用名义、各单番国内运费和多个 OPTION 参数完整。
- 实际金额同时与独立预期及后台预览核对。
- 问题产品退款和补款只从客户余额取证。
- 500 元权限场景自动切换沈文妮账号，失败后可临时输入账号密码续跑。
- 旧数据工厂、旧支付金额回归和其他数据脚本保持兼容。

## 13. 非目标与约束

- 首版只支持日本站，不开放任意参数笛卡尔积。
- 首版不新增数据智能体自然语言意图。
- 首版不同时实现 Vue 页面；保留未来迁移边界。
- 不修改密钥、环境配置和启动脚本。
- 生成业务数据保留并通过批次备注追查。
- 默认不提交、不推送。
