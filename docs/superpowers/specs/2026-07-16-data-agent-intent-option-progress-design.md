# DeepSeek 数据智能体意图、Option、退款与进度展示设计

## 背景与基线

任务 `8e2d4acbe3f64b85b6c1930109be1658` 对应聚合记录 828。DeepSeek 原始结构化结果识别到了“每番商品数量 10”和“商品数量、国内运费、option 全退”，但后端确定性纠偏将数量改为默认值 1，将问题产品数量处理改为“保持不变”。最终生成两个问题产品，只退回两笔各 5 元的国内运费，商品金额没有退款，但系统仍按错误合同判定成功。

同一任务围绕 option 连续追问。底层订单脚本已有 `order_option_counts` 能力，但数据智能体合同未注册、未查询真实 option 目录，也不能处理用户后续的取消或恢复要求。

执行弹窗每秒重新设置全部 `innerHTML`，造成滚动位置、展开状态和输入状态反复重置；长流程工具只在整体结束后更新状态，执行期间无法看到内部节点。

本设计同时吸收此前已确认的“数据智能体全中文展示”要求，形成一份统一实施基线。

## 目标

- 明确原话必须生成正确合同，模型正确结果不得被无证据规则覆盖。
- 支持订单创建时添加真实 option，并支持问题产品将商品数量、国内运费和 option 全部退款。
- 同一字段最多追问一次，最新用户决定能够更新、取消或恢复旧要求。
- 执行前发现原话与合同冲突时禁止确认。
- 执行后任一商品金额、国内运费或 option 未按合同处理时禁止成功。
- 执行弹窗稳定显示当前操作、当前节点、下一节点、总体进度和耗时，并支持最小化。
- 普通页面全部显示中文业务名称，原始字段仅保留在折叠技术日志。

## 一、意图合同与追问控制

### 1. 模型与规则优先级

DeepSeek 输出候选意图及每个字段的原文证据。后端确定性规则只有在匹配到明确原话时才允许覆盖候选值：

- 有确定性证据：使用确定性结果并记录纠偏原因。
- 只有模型证据且证据是用户原文子串：保留模型结果。
- 两边均无证据：使用明确默认值。
- 两边都有证据但含义冲突：只追问该字段，不执行。

默认值不能覆盖带原文证据的模型结果。

### 2. 数量和退款表达

数量解析覆盖：

- “每番商品数量 10”“每番 10 个”“每种买 10 件”。
- “两番商品”表示两个商品，不表示两个店铺。
- 总商品数量与每种购买数量分开保存证据。

问题产品解析覆盖：

- “商品数量、国内运费、option 全退”。
- “把两番数量、运费和 option 都清零”。
- “问题产品数量成 0”“数量改成 0”。
- 多个字段列举后在句尾统一出现“全退、都退、清零”。

### 3. 会话状态

不再把所有历史消息直接拼接后重新猜测。会话维护字段级意图状态：

- 新值覆盖旧值。
- “不要了、不添加了”只取消对应字段。
- “还是需要、恢复”重新启用对应字段。
- 已解决字段不重复追问。
- 每个字段最多追问一次；再次无法确定时显示能力说明和可选处理方式。

每次追问保存具体问题、对应字段、已识别证据和追问次数。

### 4. 执行前冲突检查

执行确认前同时比较原文证据、模型候选值和最终执行变量。出现下列情况时禁止确认：

- 原文数量 10，执行变量为 1。
- 原文要求全退，合同为数量或运费保持不变。
- 原文要求 3 个 option，合同没有 option。
- 商品总价无法根据商品种类数和购买数量精确换算到分。

## 二、订单 Option 能力

### 1. 真实目录查询

工具层增加只读 option 目录查询，复用订单脚本已有的 option 接口和目录格式，不改变订单创建业务流程。

匹配顺序：编号完全匹配、中文或日文名称完全匹配、翻译名完全匹配。模糊匹配出现多个候选时只追问一次。

### 2. 随机与指定 option

- 未指定名称的“随机 3 个 option”：从真实可用目录选择 3 个不同 option，所有商品使用同一组。
- 随机选择使用任务级固定种子，保证重试和恢复时结果一致。
- 明确写出名称时严格匹配名称，不替换成其他 option。
- 匹配结果转换为底层脚本已有的 `order_option_counts`。
- 创建订单后查询真实订单明细，确认每个商品都包含合同中的 option。

### 3. 记录 828 的真实验收口径

用户后来表示“不添加了”是因为智能体反复不理解，并非真实业务意图。修复验收以补充后的真实意图为准：每个商品添加 3 个 option。

## 三、问题产品全额退款

“商品金额、国内运费和 option 全退”固定编译为：

- `pre_num=0`，通过数量归零退回全部商品金额。
- `pre_price` 保持原商品单价。
- `pre_freight=0`，退回全部国内运费。
- `option_deal_suggest=1`，使用“按照业务修改值修改”。
- `option_new` 中所有 option 的最终计费金额必须为 0：计数型 option 将数量设为 0，固定金额型 option 将修改后金额设为 0，并保留底层接口要求的原始标识字段。

多商品按稳定 `sorting` 顺序逐条生成问题产品，并复用已有幂等恢复逻辑。

退款预览必须分别核对：

- 商品金额退款。
- 国内运费退款。
- option 金额退款。

任何一项缺失、金额不一致或商品剩余数量不为 0，立即停止，不能记录成功。权限暂停只能显示“待授权”，恢复时复用已生成的问题产品编号。

## 四、执行进度与弹窗稳定性

### 1. 后端进度事件

全流程和问题产品工具增加可选进度回调，仅供数据智能体使用，保持其他调用方兼容。每个节点更新：

- 当前操作序号和总操作数。
- 当前节点和下一节点。
- 节点状态：等待、执行中、完成、失败、待授权。
- 当前商品序号和问题产品编号。
- 开始时间、最后更新时间和已耗时。

长步骤执行期间更新心跳时间。心跳超时只显示“当前节点仍在处理中”，不能显示成功或卡死。

### 2. 前端增量更新

首次打开时构建弹窗结构，后续轮询只更新状态、进度、事件和结果区域，不重新生成整个弹窗。

必须保留：

- 滚动位置。
- 展开或折叠状态。
- 输入框内容和焦点。
- 用户正在查看的事件位置。

顶部固定进度区显示当前操作、当前节点、下一节点、总体进度、已耗时和最后更新时间。后台轮询不显示全局加载效果。

弹窗可以最小化；关闭或最小化不会停止任务。页面保留任务状态入口，用户可随时重新打开。只有明确点击“停止后续步骤”才取消任务。

失败、追问、待权限和完成状态立即停止轮询并显示明确中文状态。

## 五、全中文展示

目标合同、默认值、纠偏、工具、事件、节点、退款模式、option、权限状态和最终结果全部通过集中映射转换为中文。

未知字段不使用原代码名兜底，只显示“其他执行信息”或隐藏。订单号、配送单号、客户 ID、问题产品 ID 和测试记录 ID 作为业务编号保留原值。

测试记录识别到“DeepSeek数据智能体”时使用专用中文渲染器；折叠的“查看原始日志”继续保留原始 JSON。

## 六、执行记录与可诊断性

不修改数据库结构，在现有聚合日志中增加：

- 每次用户消息对应的字段级意图变化。
- DeepSeek 候选值和原文证据。
- 后端纠偏前后值和纠偏证据。
- 具体追问问题、字段和次数。
- option 目录匹配结果。
- 退款三部分预期值和实际值。
- 节点进度事件和心跳时间。

## 七、测试与实际体验

### 自动测试

- 使用任务 828 的完整原话作为固定回归样本。
- 覆盖每番数量、多个字段句尾统一全退、数量成 0、指定 option、随机 option、取消和恢复要求。
- 验证同一字段最多追问一次。
- 验证模型正确结果不能被无证据默认值覆盖。
- 验证 option 真实匹配及每个商品实际携带 3 个 option。
- 验证商品金额、运费、option 任一未退都不能成功。
- 验证进度事件顺序、心跳和节点状态。
- 验证轮询不重建弹窗，滚动、折叠、输入和焦点保持。
- 验证普通界面不显示代码字段。

### 真实 DeepSeek 识别

使用不少于 20 条用户口吻指令运行两轮识别，不执行业务。明确指令必须一次生成完整合同；真正歧义才允许追问，且每个字段最多一次。

### 小额业务体验

先只读查询 option 目录并选择 3 个低价真实 option，创建一条退款预览低于 500 元的测试订单：2 个商品、每个数量 2、商品总价 20、每个商品使用同一组 3 个 option，到待拍下后全退商品金额、国内运费和 option。若预览仍达到 500 元，停在待授权并更换测试数据，不自动选择部长账号。

核对真实订单明细、两条问题产品、退款预览和弹窗节点进度。记录 828 只读核验，不重复处理。

## 八、范围与约束

本次需要同时修改意图合同、工具适配、全流程进度、页面渲染和测试，文件会超过三个；这是因为五层能力必须共同闭环，不能只修提示词或前端。

不修改数据库结构、AI 配置和问题产品业务流程；option 与退款复用已有脚本能力。保留工作区全部已有改动，不提交、不推送。

此前的独立中文展示计划不再单独执行，由本设计统一覆盖。
