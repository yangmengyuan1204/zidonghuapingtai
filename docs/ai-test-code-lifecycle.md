# AI 测试代码生命周期约束

本规则约束 AI 在本项目中编写、验证和清理测试代码的行为，目标是避免临时测试文件、测试数据和调试产物长期遗留在仓库中。

## 1. 测试代码分类

- 临时测试：为定位问题、验证一次性改动或复现故障而创建的测试文件、测试函数、调试脚本、Mock 数据和本地测试数据库。
- 回归测试：用于长期保护稳定业务规则、已修复缺陷或关键接口契约的自动化测试。

## 2. 临时测试规则

- 临时测试只能服务当前需求，放在明确的临时范围内，不得混入无关业务代码。
- 验证完成后，AI 必须删除本次新增的临时测试代码及其产生的数据库、日志、截图、报告、缓存和调试脚本。
- 临时测试文件、`*.db`、日志、截图、报告和调试脚本不得提交到 Git。
- AI 不得为了测试方便修改生产环境配置、权限校验、启动脚本或业务逻辑。

## 3. 回归测试保留规则

- 回归测试可以保留，但必须覆盖稳定业务规则、关键接口契约或已修复缺陷。
- 保留的回归测试必须放在 `tests/`，使用清晰的测试名称，并在测试代码中体现被保护的业务行为。
- 回归测试应使用隔离数据、Mock 或测试环境，不得依赖真实账号、真实订单或生产数据。
- 不得把一次性调试验证伪装成回归测试长期保留。

## 4. 完成前检查

AI 完成需求前必须执行并检查：

```powershell
git status --short
git diff --stat
```

- 确认本次临时测试及其产物已经清理。
- 确认不会提交用户已有改动、数据库、日志、缓存或其他无关文件。
- 如保留了回归测试，必须在交付说明中写明其覆盖的业务行为。
