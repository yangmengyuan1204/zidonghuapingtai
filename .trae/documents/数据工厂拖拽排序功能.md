# 数据工厂脚本列表新增拖拽排序

## 摘要

在数据工厂「脚本列表」tab 中，为每行脚本新增一个拖拽手柄列（≡），用户按住手柄拖动可调整脚本顺序，排序结果通过 `flow.order` 字段持久化到 localStorage。「已隐藏」「已删除」tab 不参与排序。

## 现状分析

经探索 `d:\A_zidonghuapingtai\static\app.js` 与 `static\styles.css`：

- **flow 对象无 `order` 字段**：`readFlows()` 返回的数组顺序即展示顺序，由 `ensureXxxScript` 注入顺序 + 用户新建追加顺序决定。
- **`renderTable(columns, rows, framed=true)`**（app.js:36）：生成的 `<tr>` 无任何 `data-*` 属性，不支持行级属性；签名仅 3 个参数。
- **`visibleFlows`**（app.js:105）：`flows.filter((flow) => dataScriptProjectMatches(flow, selectedProjectId))`，无排序。
- **`normalizeDataScriptFlows(flows, projects, envs)`**（app.js:36）：规整旧 flow 的 projectId/envId，是给旧数据补 `order` 字段的合适注入点。
- **`ensureShoppingCartScript` 等 8 个 ensure 函数**（app.js:36 / 356 / 377）：新建内置脚本时 `[...flows, nextFlow]` 追加到末尾，`nextFlow = { ...existingFlow, ... }` 保留 existingFlow 所有字段。
- **事件绑定模式**（app.js:170-307）：每次 `renderDataScripts` 调用都 `querySelectorAll().forEach(addEventListener)` 全量重绑，无事件委托。`app.js:214` 有 `if (isDeletedTab || isHiddenTab) return;` 提前返回。
- **项目已有原生 HTML5 Drag and Drop 先例**：`openFunctionalScreenshotUpload`（app.js:591）中的截图上传 dropzone，模式为 `dragenter/dragover/dragleave/drop` + `event.preventDefault()` + class 切换。
- **CSS**（static/styles.css:919-920）：`tbody tr:nth-child(even)` 与 `tbody tr:hover` 已有样式，可在此基础上追加拖拽视觉反馈。

## 拟定改动

仅修改 2 个文件：`static/app.js` + `static/styles.css`。无后端变更，无新依赖。

### 改动 1：flow 新增 `order` 字段 + 旧数据兼容

**文件**：`static/app.js`（`normalizeDataScriptFlows` 函数，app.js:36 长行内）

**What**：在 `normalizeDataScriptFlows` 的 `.map((flow) => {...})` 中，给无 `order` 字段的 flow 补 `order = 当前 index`（即保留原数组顺序）。

**Why**：让旧数据按当前展示顺序获得稳定 order，无需迁移脚本。

**How**：
```js
const next = (flows || []).map((flow, index) => {
  if (!flow) return flow;
  let patched = flow;
  if (flow.order === undefined || flow.order === null) {
    patched = { ...flow, order: index };
    changed = true;
  }
  if (!patched.projectId) {
    changed = true;
    const env = (envs || []).find((item) => patched.envId && String(item.id) === String(patched.envId) && String(item.project_id) === String(projectId));
    patched = { ...patched, projectId, envId: String(env?.id || defaultEnv?.id || patched.envId || "") };
  }
  return patched;
});
```

### 改动 2：`ensureXxxScript` 新建脚本时分配 order

**文件**：`static/app.js`（8 个 ensure 函数，app.js:36 / 356 / 377 长行内）

**What**：新建内置脚本时，`nextFlow.order` 取 `Math.max(-1, ...flows.map((f) => f.order ?? -1)) + 1`，使其追加到列表末尾。

**Why**：保证新注入的内置脚本排在已有脚本之后，符合现有"追加到末尾"的视觉行为。

**How**：在每个 ensure 函数的 `const nextFlow = { ...existingFlow, ... }` 对象内追加一行 `order: existingFlow.order ?? (flows.reduce((max, f) => Math.max(max, f.order ?? -1), -1) + 1),`。

实际实现时，由于 `existingFlow` 可能已带 order（原位更新场景），用 `existingFlow.order ?? (maxOrder + 1)` 即可：原位更新保留原 order，首次注入取 maxOrder+1。

### 改动 3：`renderTable` 扩展支持行属性

**文件**：`static/app.js`（`renderTable` 函数，app.js:36 长行内）

**What**：新增第 4 参数 `rowAttrs = null`（函数 `(row) => string`），若提供则在 `<tr>` 上拼接返回的属性字符串。

**Why**：拖拽需要 `<tr data-row-id="...">` 标识行 ID；不扩展则需在列定义里塞入，会破坏表格结构。

**How**：
```js
function renderTable(columns, rows, framed = true, rowAttrs = null) {
  if (!rows.length) return framed ? `<div class="panel"><div class="empty">暂无数据</div></div>` : `<div class="empty">暂无数据</div>`;
  const head = columns.map((column) => `<th>${escapeHtml(column.label)}</th>`).join("");
  const body = rows
    .map(
      (row) => `
        <tr${rowAttrs ? ` ${rowAttrs(row)}` : ""}>
          ${columns
            .map((column) => {
              const raw = column.render ? column.render(row) : escapeHtml(short(row[column.key]));
              return `<td>${raw}</td>`;
            })
            .join("")}
        </tr>
      `,
    )
    .join("");
  return `<div class="${framed ? "panel " : ""}table-wrap"><table><thead><tr>${head}</tr></thead><tbody>${body}</tbody></table></div>`;
}
```

现有所有 `renderTable(columns, rows)` / `renderTable(columns, rows, true)` 调用点无需改动（rowAttrs 默认 null）。

### 改动 4：`visibleFlows` 按 order 排序

**文件**：`static/app.js`（app.js:105）

**What**：`visibleFlows` 计算改为 `flows.filter(...).sort((a, b) => (a.order ?? Infinity) - (b.order ?? Infinity))`。

**Why**：让展示顺序由 order 字段决定，拖拽后只需更新 order 即可生效。

**How**：
```js
const visibleFlows = flows
  .filter((flow) => dataScriptProjectMatches(flow, selectedProjectId))
  .sort((a, b) => (a.order ?? Infinity) - (b.order ?? Infinity));
```

### 改动 5：activeTable 新增拖拽手柄列 + 行属性

**文件**：`static/app.js`（app.js:112-136 的 activeTable 列定义）

**What**：
1. 在列数组最前面新增一列 `{ key: "_drag", label: "", render: (row) => `<span class="drag-handle" draggable="true" data-drag-handle="${escapeHtml(row.id)}" title="拖动排序">≡</span>` }`。
2. `renderTable` 调用新增第 4 参数：`(row) => `data-row-id="${escapeHtml(row.id)}"``。

**Why**：
- 手柄 span 设 `draggable="true"`，整行 tr 不设 draggable，避免误触发按钮拖拽。
- `data-row-id` 用于 dragover/drop 时定位目标行。
- `setDragImage(tr, 0, 0)` 让拖拽视觉影像为整行。

**How**：
```js
const activeTable = renderTable(
  [
    { key: "_drag", label: "", render: (row) => `<span class="drag-handle" draggable="true" data-drag-handle="${escapeHtml(row.id)}" title="拖动排序">≡</span>` },
    { key: "name", label: "脚本名称" },
    // ... 其余列不变
  ],
  visibleFlows,
  true,
  (row) => `data-row-id="${escapeHtml(row.id)}"`,
);
```

### 改动 6：拖拽事件绑定

**文件**：`static/app.js`（在 app.js:214 的 `if (isDeletedTab || isHiddenTab) return;` 之后、`[data-edit-script]` 绑定之前插入）

**What**：新增 4 个事件监听：`dragstart` / `dragover` / `drop` / `dragend`，绑定到 active 表格的 tbody。

**Why**：实现拖拽重排 + 视觉反馈 + 持久化。

**How**：
```js
// 拖拽排序：仅 active tab
const dragSourceId = { current: null };
document.querySelectorAll("[data-drag-handle]").forEach((handle) => {
  handle.addEventListener("dragstart", (event) => {
    const tr = handle.closest("tr");
    if (!tr) return;
    dragSourceId.current = tr.dataset.rowId;
    event.dataTransfer.effectAllowed = "move";
    event.dataTransfer.setData("text/plain", tr.dataset.rowId);
    if (event.dataTransfer.setDragImage && tr) event.dataTransfer.setDragImage(tr, 0, 0);
    tr.classList.add("dragging");
  });
});
const activeTbody = document.querySelector('#content tbody');
if (activeTbody) {
  activeTbody.addEventListener("dragover", (event) => {
    event.preventDefault();
    event.dataTransfer.dropEffect = "move";
    const targetTr = event.target.closest("tr");
    if (!targetTr || !targetTr.dataset.rowId) return;
    if (targetTr.dataset.rowId === dragSourceId.current) return;
    activeTbody.querySelectorAll("tr.drag-over").forEach((tr) => tr.classList.remove("drag-over"));
    targetTr.classList.add("drag-over");
  });
  activeTbody.addEventListener("drop", async (event) => {
    event.preventDefault();
    const targetTr = event.target.closest("tr");
    if (!targetTr || !targetTr.dataset.rowId) return;
    const sourceId = dragSourceId.current;
    const targetId = targetTr.dataset.rowId;
    if (!sourceId || sourceId === targetId) return;
    const flows = readFlows();
    const selectedProjectId = state.filters.projectId || "";
    const visibleFlows = flows
      .filter((flow) => dataScriptProjectMatches(flow, selectedProjectId))
      .sort((a, b) => (a.order ?? Infinity) - (b.order ?? Infinity));
    const sourceIdx = visibleFlows.findIndex((flow) => flow.id === sourceId);
    const targetIdx = visibleFlows.findIndex((flow) => flow.id === targetId);
    if (sourceIdx < 0 || targetIdx < 0) return;
    const [moved] = visibleFlows.splice(sourceIdx, 1);
    visibleFlows.splice(targetIdx, 0, moved);
    // 按新顺序重新分配 order（仅可见行）
    visibleFlows.forEach((flow, index) => { flow.order = index; });
    // 合并回 flows：保留不可见 flow 的原 order
    const visibleById = new Map(visibleFlows.map((flow) => [flow.id, flow]));
    const nextFlows = flows.map((flow) => visibleById.get(flow.id) || flow);
    writeFlows(nextFlows);
    showToast("排序已更新");
    await renderDataScripts();
  });
  activeTbody.addEventListener("dragend", () => {
    dragSourceId.current = null;
    activeTbody.querySelectorAll("tr.dragging, tr.drag-over").forEach((tr) => tr.classList.remove("dragging", "drag-over"));
  });
}
```

## 假设与决策

- **原生 HTML5 Drag and Drop**：项目已有先例（截图上传），无新依赖。不引入 SortableJS。
- **手柄列方案**：手柄 span `draggable="true"`，tr 不设 draggable，避免误触按钮拖拽。`setDragImage(tr)` 让拖拽影像为整行。
- **仅 active tab 排序**：hidden/deleted 是归档区，不排序。事件绑定在 `if (isDeletedTab || isHiddenTab) return;` 之后。
- **flow.order 字段**：数值型，越小越靠前。旧数据在 `normalizeDataScriptFlows` 中按 index 补值，保留原顺序。
- **重排粒度**：仅在当前项目筛选下重排可见脚本；不可见脚本（其他项目）的 order 保持不变。可见脚本 order 按新顺序重新分配为 0..n-1，可能与不可见脚本的 order 冲突，但 `visibleFlows.sort` 只比较可见集合内 order，不影响展示。下次切换项目时各项目内 order 仍相对有序。
- **事件绑定位置**：在 `if (isDeletedTab || isHiddenTab) return;` 之后，确保仅 active tab 绑定。`dragover`/`drop`/`dragend` 委托到 `#content tbody`（active 表格唯一的 tbody）。
- **不主动 push**：遵循 AGENTS.md。
